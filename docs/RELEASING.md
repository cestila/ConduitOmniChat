# Releasing ConduitOmniChat

This document describes how the public repositories are produced and published.
Four repositories are published under the `cestila` account:

| Repository | Content |
|---|---|
| `cestila/ConduitOmniChat` | `sdk/`, `core/` (conduitd), `gui/`, `docs/` |
| `cestila/conduit-plugin-whatsapp` | WhatsApp plugin |
| `cestila/conduit-plugin-telegram` | Telegram plugin |
| `cestila/conduit-plugin-discord` | Discord plugin (currently a demo, see below) |

The private monorepo history is **not** published. Every public repository is
generated by `scripts/export-public.sh` from the committed `HEAD` of the private
monorepo and starts with a single commit, `Initial public release`, authored by
`Carlos Estilarte <cestila@gmail.com>`. The script never pushes, never creates
remote repositories and never touches the monorepo's git history.

## First publication

### 0. Prerequisites

- The work to publish is committed in the private monorepo (the export reads
  `git archive HEAD`, never the working tree).
- `gh auth status` shows you are logged in as `cestila`.
- `go`, `git`, `tar`, `make` and (optionally for `--with-gui`) `node`/`npm`.

### 1. Export the main repository

```sh
scripts/export-public.sh main dist-public            # add --with-gui to also run the GUI tests
```

This creates `dist-public/ConduitOmniChat`, runs the leak guard, makes the
single commit and runs `go vet` + `go test` for `sdk` and `core`. Read the
summary table at the end; every repository must report `PASS`.

### 2. Create and push the main repository

```sh
gh repo create cestila/ConduitOmniChat --public \
  --source dist-public/ConduitOmniChat --remote origin --push
```

Then enable private vulnerability reporting (referenced by `SECURITY.md`):

```sh
gh api -X PUT repos/cestila/ConduitOmniChat/private-vulnerability-reporting
```

### 3. Tag the SDK and the first release

The SDK lives in a subdirectory, so Go requires the tag `sdk/vX.Y.Z`. The plain
`vX.Y.Z` tag triggers the release workflow, which builds `conduitd` and the GUI.

```sh
cd dist-public/ConduitOmniChat
git tag sdk/v0.1.0
git tag v0.1.0
git push origin sdk/v0.1.0 v0.1.0
```

### 4. Wait for the Go module proxy

```sh
GOPROXY=https://proxy.golang.org go list -m github.com/cestila/ConduitOmniChat/sdk@v0.1.0
```

Repeat until it prints the module line. Only then can the plugins resolve the SDK.

### 5. Export the plugin repositories

```sh
scripts/export-public.sh plugins dist-public --sdk-version v0.1.0
```

Each plugin `go.mod` is rewritten: the `replace ... => ../../sdk` is dropped and
`github.com/cestila/ConduitOmniChat/sdk v0.1.0` is required, followed by
`go get` and `go mod tidy` with `GOWORK=off`. If this fails, the main repository
and the `sdk/v0.1.0` tag are not published yet; go back to steps 2-4.

To dry-run before publishing anything, use the local SDK instead of the network:

```sh
scripts/export-public.sh plugins /tmp/conduit-dry-run --local-sdk dist-public/ConduitOmniChat
```

(a temporary `go.work` outside the exported repos is used for the checks; the
exported `go.mod` still requires the published version).

### 6. Create, push and tag each plugin repository

```sh
for id in whatsapp telegram discord; do
  gh repo create "cestila/conduit-plugin-$id" --public \
    --source "dist-public/conduit-plugin-$id" --remote origin --push
  (cd "dist-public/conduit-plugin-$id" && git tag v0.1.0 && git push origin v0.1.0)
done
```

The tag triggers each plugin's GoReleaser workflow, which publishes
`conduit-plugin-<id>_<version>_<goos>_<goarch>.tar.gz` and `checksums.txt`.
The Discord plugin is currently a demo (see its `README.md`); publishing it is
optional, so drop `discord` from the loop (and delete `dist-public/conduit-plugin-discord`)
if you prefer to wait.

### 7. Verify against the real release

```sh
conduitd plugin install telegram
conduitd plugin list
```

The installer must download the asset and `checksums.txt` from the GitHub
release, verify the SHA-256 and place the binary in `<dataDir>/plugins/`.

## Later releases

- **Only a plugin changed:** commit in the plugin's public repo (or in the
  monorepo and re-export), tag `vX.Y.Z`, push the tag.
- **SDK changed:** release the main repo first and tag `sdk/vX.Y.Z` (and
  `vX.Y.Z` if `conduitd`/GUI changed). Wait for the proxy (step 4). Then in each
  plugin run `go get github.com/cestila/ConduitOmniChat/sdk@vX.Y.Z && go mod tidy`,
  and tag the plugin.
- **ProtocolVersion:** a backwards-compatible change (new optional RPC or field)
  does not bump `ProtocolVersion`. A breaking change to `sdk/proto/conduit.proto`
  or the handshake bumps it, which makes old plugins and a new `conduitd`
  incompatible; in that case release the SDK, `conduitd` and every plugin
  together, and note it in the release notes.
- Never re-tag a published version; the Go proxy caches modules permanently.

## Development after publication

Development continues in the public repositories. For cross-repo work, check
the repos out side by side and use a local `go.work` (never commit it):

```
// ~/src/conduit/go.work
go 1.26

use (
	./ConduitOmniChat/sdk
	./ConduitOmniChat/core
	./conduit-plugin-telegram
)
```

## Maintainer-only: `CONDUIT_EXPORT_ALLOW_DIRTY=1`

The export refuses to run if the exported paths have uncommitted changes. The
variable `CONDUIT_EXPORT_ALLOW_DIRTY=1` skips that guard and exists only for
`scripts/export-public_test.sh`. The export still reads committed `HEAD`, so
uncommitted work is never included. Do not use it for a real release.
